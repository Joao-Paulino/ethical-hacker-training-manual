2. Contexto e Relevância / Context and Relevance Original

Os defensores beneficiam imenso de aprender as mesmas técnicas que os atacantes usam, mas do lado oposto. Quando um atacante tem footholds numa organização, raramente depende de um único mecanismo — constrói múltiplos fallbacks. Já vimos casos em que os incident responders removeram scheduled tasks e serviços, mas credenciais esquecidas e ferramentas de acesso remoto como o AnyDesk permitiram aos atacantes reentrar dias depois. Também vimos atacantes plantarem processos auxiliares (watchdogs) que ressuscitam payloads após remoções. Por isso, trata o ambiente como se fosse "radioativo": assume que há sobreviventes e procura-os em todo o lado. Defenders benefit immensely from learning the same techniques attackers use, but from the other side. When an attacker has footholds across an estate, they rarely rely on a single mechanism — they build multiple fallbacks. We've seen cases where incident responders removed scheduled tasks and services, but forgotten credentials and remote-access tools like AnyDesk allowed attackers to re-enter days later. We've also seen attackers plant helper processes (watchdogs) that resurrect payloads after removals. So treat the environment as if it were "radioactive": assume there are survivors and look for them everywhere.

3. DeepBlueCLI — Análise de Logs Original

O DeepBlueCLI é uma ferramenta PowerShell criada para ajudar defensores a identificar rapidamente comportamento suspeito em logs de eventos do Windows. A sua força está na simplicidade: não precisas de configurações complexas, ficheiros de regras longos, ou conhecimento profundo de internals do Windows. Mapeia padrões de ataque comuns diretamente para indicadores de log, apresentando os resultados de forma fácil de ler e agir. DeepBlueCLI is a PowerShell-based tool created to help defenders quickly identify suspicious behavior in Windows event logs. Its strength lies in simplicity: you don't need complex configurations, long rule files, or a deep understanding of Windows internals. It maps common attack patterns directly to log indicators, presenting results in a way that's easy to read and act upon.

3.1 Análise de log exportado / Exported log analysis

PS > .\DeepBlue.ps1 -file .\evtx\sliver-security.evtx
O output mostra indicadores: cmd.exe a aceder ao share ADMIN$ (movimento lateral), cmd.exe via WMI através de WmiPrvSE.exe (execução remota), e cmd.exe /Q /c JOINT_BALL.exe (payload Sliver). The output shows indicators: cmd.exe accessing ADMIN$ share (lateral movement), cmd.exe via WMI through WmiPrvSE.exe (remote execution), and cmd.exe /Q /c JOINT_BALL.exe (Sliver payload).

3.2 Análise de ofuscação / Obfuscation analysis

PS > .\DeepBlue.ps1 -file .\evtx\Powershell-Invoke-Obfuscation-many.evtx
Linhas de comando muito longas com nomes fortemente modificados (variantes de iNVOke). Passam por frameworks de ofuscação, tornando-os difíceis de detetar com regras simples. Very long command lines with heavily modified names (iNVOke variants). They pass through obfuscation frameworks, making them hard to detect with simple rules.

Destaca imediatamente brute-force: várias contas com tentativas de logon falhadas. O DeepBlueCLI conta o total, dando uma visão geral imediata. Immediately highlights brute-force: several accounts with failed logon attempts. DeepBlueCLI counts the total, giving an immediate overview.

4. WELA — Auditoria e Hardening Original

O WELA é um script PowerShell da Yamato Security que foca em auditar e endurecer sistemas Windows. Ao contrário do DeepBlueCLI (que olha para o passado), o WELA ajuda a compreender a postura de segurança atual e guia-te para a melhorar. Audita configurações contra uma baseline e destaca áreas fora dos padrões. É frequentemente sinalizado por antivírus (usa técnicas avançadas), mas é legítimo e defensivo. WELA is a PowerShell script from Yamato Security that focuses on auditing and hardening Windows systems. Unlike DeepBlueCLI (which looks at the past), WELA helps you understand the current security posture and guides you to improve it. It audits settings against a baseline and highlights areas outside standards. It's often flagged by antivirus (uses advanced techniques), but it's legitimate and defensive. 
PS > .\WELA.ps1 -Help
O WELA analisa configurações como PowerShell v2 (que deve ser desativado), Sysmon, e outras opções. O relatório começa com uma visão geral da saúde de segurança do sistema. WELA analyzes settings like PowerShell v2 (which should be disabled), Sysmon, and other options. The report starts with a high-level overview of the system's security health.

5. PersistenceSniper — Encontrar Persistência Original

O PersistenceSniper é um módulo PowerShell moderno que enumera localizações de persistência conhecidas e apresenta-as de forma amigável. Percorre serviços, scheduled tasks, chaves Run, Winlogon, pastas Startup, subscrições WMI, AppInit DLLs, e mais. Devolve resultados estruturados, anota itens suspeitos e mapeia achados para ATT&CK. PersistenceSniper is a modern PowerShell module that enumerates known persistence locations and presents them in analyst-friendly form. It walks services, scheduled tasks, Run keys, Winlogon, Startup folders, WMI subscriptions, AppInit DLLs, and more. It returns structured results, notes suspicious items, and maps findings to ATT&CK.

5.1 Instalação / Installation

PS > powershell -ep bypass
PS > Install-Module -Name PersistenceSniper -Scope CurrentUser -Force -SkipPublisherCheck
PS > Import-Module PersistenceSniper

5.2 Scan

PS > Find-AllPersistence -Verbose
O output é verboso: verás entradas para binários de sistema legítimos, mas nem tudo é hostil. O PersistenceSniper classifica e mapeia alterações ao BootExecute para T1547.001. Usa-o como primeira passagem no triage. The output is verbose: you'll see entries for legitimate system binaries, but not everything is hostile. PersistenceSniper classifies and maps BootExecute changes to T1547.001. Use it as a first pass during triage.

6. Trawler — Caça com Menos Ruído Original

O Trawler aborda o mesmo problema com ênfase diferente: reduz o ruído e apresenta apenas itens que parecem persistência de adversário. Útil para caçar em escala. O trade-off é que pode produzir falsos negativos se o atacante imitar um item allow-listed. Qualquer achado precisa de validação humana. Suporta scan de imagens offline e drives montados. Trawler approaches the same problem with a different emphasis: reduces noise and presents only items that look like adversary persistence. Useful for hunting at scale. The trade-off is it can produce false negatives if the attacker mimics an allow-listed item. Any finding needs human validation. Supports scanning offline images and mounted drives. 
PS > .\trawler.ps1
Permite vários minutos. Se testaste o mesmo método de persistência, espera que apareça perto do fim. Usa o Trawler para um conjunto compacto de leads de alta confiança. Allow several minutes. If you tested the same persistence method, expect it near the end. Use Trawler for a compact set of high-confidence leads.

7. Kansa — Resposta em Escala Original

O Kansa é um framework modular de resposta a incidentes em PowerShell que se destaca na recolha de artefactos forenses em muitos hosts usando WinRM. Enquanto o PersistenceSniper e o Trawler focam no host local, o Kansa é a ferramenta para extrair os mesmos artefactos de centenas de computadores e agregar resultados. Kansa is a modular incident-response framework in PowerShell that excels at collecting forensic artifacts across many hosts using WinRM. While PersistenceSniper and Trawler focus on the local host, Kansa is the tool to pull the same artifacts from hundreds of computers and aggregate results.

9. AD ACL Scanner — Abuso de DACL Original

O abuso de DACL em Active Directory é perigoso e frequentemente ignorado. Uma DACL define quem pode aceder a um objeto AD e que ações pode executar. O abuso ocorre quando atacantes manipulam permissões para obter controlo persistente e invisível. Detetar é difícil sem monitorizar objetos de alto valor. DACL abuse in Active Directory is dangerous and often overlooked. A DACL defines who can access an AD object and what actions they can perform. Abuse occurs when attackers manipulate permissions to gain persistent and invisible control. Detection is hard without monitoring high-value objects.

9.1 AdminSDHolder

O AdminSDHolder protege contas privilegiadas aplicando um security descriptor consistente. Atacantes gostam dele porque GenericAll sobre o AdminSDHolder concede controlo de longo prazo sobre contas privilegiadas. AdminSDHolder protects privileged accounts by enforcing a consistent security descriptor. Attackers like it because GenericAll over AdminSDHolder grants long-term control over privileged accounts.

9.2 Machine Account Quota (MAQ)

Por omissão, cada utilizador de domínio tem MAQ = 10 (pode criar até 10 objetos de computador). Isto simplifica joins legítimos, mas abre caminhos de ataque (RBCD, shadow credentials). Reduzir MAQ para 0 remove muitos vetores. By default, every domain user has MAQ = 10 (can create up to 10 computer objects). This simplifies legitimate joins but opens attack paths (RBCD, shadow credentials). Reducing MAQ to 0 removes many vectors.

10. Scripts de Impacto / Impact Scripts Impacto Complementar

As ferramentas originais são excelentes, mas por vezes precisas de uma verificação rápida e nativa, sem depender de módulos externos. Os scripts abaixo replicam a lógica defensiva em PowerShell puro, com output legível e exportação para relatório. The original tools are excellent, but sometimes you need a quick, native check without depending on external modules. The scripts below replicate defensive logic in pure PowerShell, with readable output and report export.

10.1 Script 6.1 — Deteção de Brute-Force e Spraying / Brute-Force & Spraying Detection

Objetivo: analisar eventos 4625 (failed logon) e 4648 (explicit credentials) e agrupar por conta/IP para detetar brute-force e password spraying. Evidência: logon-alerts.csv. Goal: analyze events 4625 (failed logon) and 4648 (explicit credentials) and group by account/IP to detect brute-force and password spraying. Evidence: logon-alerts.csv. 
# Script 6.1 - Logon Anomaly Detection
$log = "Security"
$out = ".\logon-alerts.csv"
$events = Get-WinEvent -LogName $log -MaxEvents 5000 -ErrorAction SilentlyContinue |
    Where-Object { $_.Id -in @(4625,4648) }
$results = foreach ($e in $events) {
    $xml = [xml]$e.ToXml()
    $data = @{}
    $xml.Event.EventData.Data | ForEach-Object { $data[$_.Name] = $_.'#text' }
    [PSCustomObject]@{
        TimeCreated = $e.TimeCreated
        EventId     = $e.Id
        TargetUser  = $data['TargetUserName']
        IpAddress   = $data['IpAddress']
        Process     = $data['ProcessName']
    }
}
$results | Group-Object TargetUser, IpAddress |
    Where-Object { $_.Count -gt 3 } |
    ForEach-Object {
        [PSCustomObject]@{
            TargetUser = $_.Group[0].TargetUser
            IpAddress  = $_.Group[0].IpAddress
            FailCount  = $_.Count
            FirstSeen  = ($_.Group | Measure-Object TimeCreated -Minimum).Minimum
            LastSeen   = ($_.Group | Measure-Object TimeCreated -Maximum).Maximum
        }
    } | Sort-Object FailCount -Descending | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Saved: $out" -ForegroundColor Green
Get-Content $out

10.2 Script 6.2 — Persistência Rápida / Quick Persistence Sweep

Objetivo: verificar nativamente Run keys (HKLM/HKCU), Winlogon (Shell/Userinit), pastas Startup e Scheduled Tasks não desativadas. Evidência: persistence-quick.csv. Goal: natively check Run keys (HKLM/HKCU), Winlogon (Shell/Userinit), Startup folders, and enabled Scheduled Tasks. Evidence: persistence-quick.csv. 
# Script 6.2 - Quick Persistence Sweep
$out = ".\persistence-quick.csv"
$results = @()

# Run keys
$runKeys = @(
    "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run",
    "HKLM:\Software\Microsoft\Windows\CurrentVersion\RunOnce",
    "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run",
    "HKCU:\Software\Microsoft\Windows\CurrentVersion\RunOnce"
)
foreach ($k in $runKeys) {
    if (Test-Path $k) {
        (Get-ItemProperty $k).PSObject.Properties |
            Where-Object { $_.Name -notmatch '^PS' } |
            ForEach-Object { $results += [PSCustomObject]@{ Type="RunKey"; Path=$k; Name=$_.Name; Value=$_.Value } }
    }
}

# Winlogon
$wl = "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"
if (Test-Path $wl) {
    $p = Get-ItemProperty $wl
    foreach ($n in @("Shell","Userinit")) {
        if ($p.$n) { $results += [PSCustomObject]@{ Type="Winlogon"; Path=$wl; Name=$n; Value=$p.$n } }
    }
}

# Startup folders
$startups = @("$env:ProgramData\Microsoft\Windows\Start Menu\Programs\Startup") + (Get-ChildItem "C:\Users" -Directory -EA SilentlyContinue | ForEach-Object { "$($_.FullName)\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup" })
foreach ($s in $startups) {
    if (Test-Path $s) {
        Get-ChildItem $s -File -EA SilentlyContinue |
            ForEach-Object { $results += [PSCustomObject]@{ Type="StartupFolder"; Path=$s; Name=$_.Name; Value=$_.FullName } }
    }
}

# Scheduled Tasks
Get-ScheduledTask -EA SilentlyContinue | Where-Object { $_.State -ne "Disabled" } |
    ForEach-Object {
        $results += [PSCustomObject]@{ Type="ScheduledTask"; Path=$_.TaskPath; Name=$_.TaskName; Value=($_.Actions.Execute -join ";") }
    }

$results | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Saved: $out ($($results.Count) items)" -ForegroundColor Green

10.3 Script 6.3 — Auditoria de ACLs de Alto Valor / High-Value ACL Audit

Objetivo: listar permissões perigosas (GenericAll, WriteDACL, WriteOwner) em objetos de alto valor (Domain Admins, AdminSDHolder, DCs). Requer o módulo ActiveDirectory (RSAT). Evidência: acl-findings.csv. Goal: list dangerous permissions (GenericAll, WriteDACL, WriteOwner) on high-value objects (Domain Admins, AdminSDHolder, DCs). Requires ActiveDirectory module (RSAT). Evidence: acl-findings.csv. 
# Script 6.3 - High-Value ACL Audit
Import-Module ActiveDirectory -ErrorAction Stop
$out = ".\acl-findings.csv"
$targets = @("Domain Admins","Enterprise Admins","AdminSDHolder")
$results = @()
$dangerous = @("GenericAll","WriteDACL","WriteOwner","GenericWrite")

foreach ($t in $targets) {
    try {
        $obj = Get-ADObject -Filter "Name -eq '$t'" -Properties nTSecurityDescriptor -EA Stop
        $acl = $obj.nTSecurityDescriptor.Access
        foreach ($ace in $acl) {
            if ($ace.AccessControlType -eq "Allow" -and $ace.ActiveDirectoryRights -in $dangerous) {
                $results += [PSCustomObject]@{
                    Target    = $t
                    Trustee   = $ace.IdentityReference
                    Right     = $ace.ActiveDirectoryRights
                    Severity  = if ($ace.ActiveDirectoryRights -eq "GenericAll") { "CRITICAL" } else { "HIGH" }
                }
            }
        }
    } catch { Write-Warning "Failed: $t - $($_.Exception.Message)" }
}

# MAQ
$maq = (Get-ADDomain).DistinguishedName
$maqVal = (Get-ADObject -Identity $maq -Properties ms-DS-MachineAccountQuota).'ms-DS-MachineAccountQuota'
$results += [PSCustomObject]@{ Target="Domain"; Trustee="MachineAccountQuota"; Right="MAQ=$maqVal"; Severity=if($maqVal -gt 0){"HIGH"}else{"OK"} }

$results | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Saved: $out" -ForegroundColor Green
$results | Format-Table -AutoSize

12. Mitigações Blue Team / Mitigations Complementar

  1. Ativar Script Block Logging (4104) e Module Logging (4103) — essencial para DeepBlueCLI e Script 6.1.
  2. Desativar PowerShell 2.0 — evita downgrade attacks.
  3. Implementar Sysmon — melhora drasticamente a telemetria.
  4. Reduzir MAQ para 0 — remove vetores de ataque em AD.
  5. Monitorizar AdminSDHolder — alterações são críticas.
  6. Auditar ACLs regularmente — usar ADACLScanner ou Script 6.3.
  7. Correr WELA e audit.ps1 periodicamente — baseline de hardening.
  8. Usar PersistenceSniper/Trawler no triage — primeira passagem rápida.
  9. Kansa para resposta em escala — recolha centralizada via WinRM.
  10. Honeytokens em AdminSDHolder e MAQ — deteta abuso.
