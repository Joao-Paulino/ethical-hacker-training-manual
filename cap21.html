2. Contexto e Relevância / Context and Relevance Original

Durante engagements red team, muitas vezes temos de lidar com os logs que os diferentes sistemas operativos armazenam. Cada ação pode deixar evidência digital. Essa evidência é exatamente aquilo em que as equipas azuis e os investigadores forenses se baseiam para reconstruir um ataque. Por vezes, um engagement red team destina-se a simular um adversário o mais realisticamente possível. Os hackers tentam frequentemente esconder o que fizeram apagando evidência ou alterando artefactos forenses para dificultar as investigações. Se queremos avaliar com precisão a capacidade de uma organização detetar intrusões sofisticadas, também precisamos de testar quão bem responde quando um atacante tenta remover esses rastos. During red team engagements, we often have to deal with the logs that different operating systems store. Every action can leave behind digital evidence. That evidence is exactly what blue teams and digital forensics investigators rely on when reconstructing an attack. Sometimes, a red team engagement is meant to simulate an adversary as realistically as possible. Hackers frequently attempt to hide what they did by erasing evidence or altering forensic artifacts to make investigations more difficult. If we want to accurately evaluate an organization's ability to detect sophisticated intrusions, we also need to test how well it responds when an attacker attempts to remove those traces.

3. O que é Nyx Original

O Nyx é um script self-contained para limpar rastos forenses em Linux, macOS e Windows. Os scripts percorrem uma coleção predefinida de artefactos forenses e removem ou limpam evidência que possa ter sido gerada durante o uso do sistema. Nenhuma ferramenta anti-forense pode garantir que todos os rastos desaparecem. Ambientes empresariais modernos recolhem telemetria de muitas fontes, incluindo EDR, servidores de logs centralizados, monitorização de rede, cloud e backups. Mesmo que os artefactos locais sejam modificados ou apagados, a evidência pode ainda existir noutro lado. Nyx is a self-contained script for cleaning forensic traces on Linux, macOS, and Windows. The scripts walk through a predefined collection of forensic artifacts and remove or clean evidence that may have been generated during system usage. No anti-forensics tool can guarantee that every trace of activity disappears. Modern enterprise environments collect telemetry from many different sources including EDR, centralized log servers, network monitoring, cloud services, and backup solutions. Even if local artifacts are modified or deleted, evidence may still exist elsewhere.

5. Uso Original Complementar

Antes de limpar, corre sempre o -DryRun para ver o que será limpo sem modificar nada. Before cleaning, always run -DryRun to see what will be cleaned without modifying anything. 
# Download
PS > iwr https://raw.githubusercontent.com/evilsocket/nyx/refs/heads/main/nyx.ps1 -OutFile nyx.ps1

# DryRun
PS > .\nyx.ps1 -DryRun

# Execução real
PS > .\nyx.ps1

# Forçar (sem prompt) e log
PS > .\nyx.ps1 -Force -LogFile "nyx-audit.log"

# Módulos específicos
PS > .\nyx.ps1 -Modules events,history -Force

# Modo avançado
PS > .\nyx.ps1 -Advanced -Force
A execução em memória também é possível (iwr ... | iex), mas o artigo nota que isso não garante invisibilidade — EDR moderno monitoriza comportamento, AMSI e memória, não apenas ficheiros. In-memory execution is also possible (iwr ... | iex), but the article notes it doesn't guarantee invisibility — modern EDR monitors behavior, AMSI, and memory, not just files.

6. Limitações Complementar

A análise técnica do Nyx identifica limitações importantes: não há secure erase (apenas rm/truncate/Clear-Content), não limpa espaço livre, não trata $LogFile ou $MFT slack em NTFS, e a limpeza de logs de EDR é muitas vezes ineficaz porque estes mantêm telemetria em kernel/cloud. Technical analysis of Nyx identifies important limitations: no secure erase (only rm/truncate/Clear-Content), doesn't wipe free space, doesn't handle $LogFile or $MFT slack on NTFS, and EDR log cleaning is often ineffective because they keep telemetry in kernel/cloud.

7. Scripts de Impacto / Impact Scripts Impacto Complementar

Os scripts abaixo ajudam o blue team a detetar atividade de limpeza de artefactos forenses. The scripts below help the blue team detect forensic artifact cleaning activity.

7.1 Script 21.1 — Deteção de Limpeza de Logs / Log Clearing Detection

Objetivo: detetar eventos 1102 (Security log cleared) e 104 (System log cleared). Evidência: log-cleared.csv. Goal: detect events 1102 (Security log cleared) and 104 (System log cleared). Evidence: log-cleared.csv. 
# Script 21.1 - Log Clearing Detection
$out = ".\log-cleared.csv"
$hits = @()
Get-WinEvent -LogName Security -MaxEvents 500 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 1102 } | ForEach-Object {
    $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Event="1102"; Log="Security" }
  }
Get-WinEvent -LogName System -MaxEvents 500 -EA SilentlyContinue |
  Where-Object { $_.Id -eq 104 } | ForEach-Object {
    $hits += [PSCustomObject]@{ Time=$_.TimeCreated; Event="104"; Log="System" }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Log cleared events: $($hits.Count) -> $out" -ForegroundColor Red

7.2 Script 21.2 — Deteção de Prefetch Vazio / Empty Prefetch Detection

Objetivo: verificar se a pasta Prefetch está vazia ou com poucos ficheiros (indicador de limpeza). Evidência: output no ecrã. Goal: check if the Prefetch folder is empty or has very few files (cleaning indicator). Evidence: on-screen output. 
# Script 21.2 - Empty Prefetch Detection
$pf = Get-ChildItem "C:\Windows\Prefetch\*.pf" -EA SilentlyContinue
$count = $pf.Count
if ($count -lt 10) {
  Write-Host "[!] Prefetch has only $count files - possible cleaning" -ForegroundColor Red
} else {
  Write-Host "[+] Prefetch has $count files - normal" -ForegroundColor Green
}
$pf | Select-Object -First 5 Name, LastWriteTime | Format-Table -AutoSize

7.3 Script 21.3 — Deteção de PSReadLine Vazio / Empty PSReadLine Detection

Objetivo: verificar se o histórico do PowerShell foi limpo (ficheiro vazio ou inexistente). Evidência: output no ecrã. Goal: check if PowerShell history was cleared (empty or missing file). Evidence: on-screen output. 
# Script 21.3 - Empty PSReadLine Detection
$hist = "$env:APPDATA\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt"
if (-not (Test-Path $hist)) {
  Write-Host "[!] PSReadLine history file MISSING - possible cleaning" -ForegroundColor Red
} elseif ((Get-Item $hist).Length -eq 0) {
  Write-Host "[!] PSReadLine history file is EMPTY - possible cleaning" -ForegroundColor Red
} else {
  Write-Host "[+] PSReadLine history has $((Get-Item $hist).Length) bytes - normal" -ForegroundColor Green
}

9. Mitigações Blue Team / Mitigations Complementar

  1. Centralizar logs no SIEM — o Nyx limpa logs locais, mas o SIEM preserva a evidência.
  2. Monitorizar eventos 1102 e 104 — Script 21.1.
  3. Alertar sobre Prefetch vazio — Script 21.2.
  4. Alertar sobre PSReadLine vazio — Script 21.3.
  5. Ativar Credential Guard — protege contra extração pós-limpeza.
  6. Monitorizar execução de wevtutil cl via Sysmon/EDR.
  7. Honeytokens — logs canário, Prefetch falsos.
