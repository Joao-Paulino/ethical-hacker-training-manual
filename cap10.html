2. Contexto e Relevância / Context and Relevance Original

Este ataque depende da modificação de propriedades de contas de utilizador no Active Directory, pelo que precisas de privilégios de Domain Admin. Normalmente, quando um atacante compromete uma conta de Domain Admin, o jogo acabou para a organização. Mas mesmo com esse nível de privilégio, há alturas em que queres credenciais de um utilizador específico sem acionar ações de alto risco óbvias. Os defensores monitorizam NTDS dump, LSASS e DCSync. Há situações em que esses métodos estão bloqueados, monitorizados ou simplesmente não são ideais. Este script existe exatamente para esses casos: obtém hashes de forma mais silenciosa, misturando-se com o comportamento normal do domínio. This attack relies on modifying user account properties in Active Directory, so you need Domain Admin privileges. Normally, when an attacker compromises a Domain Admin account, the game is over for the organization. But even with that level of privilege, there are times when you want credentials for a specific user without triggering obvious high-risk actions. Defenders monitor NTDS dump, LSASS, and DCSync. There are situations where those methods are blocked, monitored, or simply not ideal. This script exists exactly for those cases: it retrieves hashes more quietly, blending into normal domain behavior.

3. O que é Timeroasting Original

O Timeroasting foi originalmente desenhado para obter hashes de computadores de domínio, não de utilizadores. Abusa de uma fraqueza na forma como certas contas de computador e de trust armazenam passwords no AD. Essas passwords de máquina são depois usadas para calcular material de autenticação MS-SNTP, que os atacantes podem recolher e tentar crackear offline. Normalmente, as contas de computador têm passwords longas e aleatórias, tornando o cracking impraticável. Mas sistemas antigos (Pre-Windows 2000 Computers) armazenavam por vezes passwords fracas ou previsíveis. Foi descoberto e documentado por Tom Tervoort (Secura). Timeroasting was originally designed to obtain hashes from domain computers, not users. It abuses a weakness in how certain computer and trust accounts store passwords in AD. These machine passwords are then used to compute MS-SNTP authentication material, which attackers can collect and attempt to crack offline. Normally, computer accounts have long, random passwords, making cracking impractical. But older systems (Pre-Windows 2000 Computers) sometimes stored weak or predictable passwords. It was discovered and documented by Tom Tervoort (Secura).
Limitação / Limitation:
Para sistemas modernos, as passwords de máquina são longas e complexas. Correr esses hashes por wordlists poderosas pode levar muito tempo e falhar. Por isso, o uso do Timeroasting original era bastante limitado. For modern systems, machine passwords are long and complex. Running those hashes through powerful wordlists can take a very long time and fail. That's why original Timeroasting use was quite limited.

4. Targeted Timeroasting Original

Esta limitação foi resolvida por Giulio Pierantoni, que demonstrou que contas de utilizador de domínio também podiam ser abusadas de forma semelhante. Como os Domain Admins podem modificar atributos de contas de utilizador, podes temporariamente converter uma conta de utilizador em algo que parece uma conta de máquina de domínio, convencer o DC a tratá-la como tal e devolver um hash. O DC acredita que a conta é um computador, expondo material de autenticação normalmente associado a contas de máquina — mas agora pertence a um utilizador humano. This limitation was addressed by Giulio Pierantoni, who demonstrated that domain user accounts could also be abused similarly. Since Domain Admins can modify user account attributes, you can temporarily convert a user account into something that looks like a domain machine account, convince the DC to treat it as such, and return a hash. The DC believes the account is a computer, exposing authentication material normally associated with machine accounts — but now it belongs to a human user.

4.1 Mecânica / Mechanics

Cada objeto de utilizador AD tem um campo sAMAccountType que define o tipo de conta. Utilizadores normais e contas de máquina têm valores diferentes. Não podes modificar diretamente este campo, mas há outro atributo: userAccountControl. Quando o valor é alterado para a flag que representa uma workstation trust account, o sAMAccountType é atualizado automaticamente. O DC passa a acreditar que está a lidar com uma conta de máquina. Every AD user object has an sAMAccountType field defining the account type. Normal users and machine accounts have different values. You can't modify this field directly, but there's another attribute: userAccountControl. When the value is changed to the flag representing a workstation trust account, sAMAccountType is automatically updated. The DC then believes it's dealing with a machine account.
Antes de calcular o hash, o DC também verifica que o sAMAccountName termina com um cifrão ($). Para Domain Admins, alterar isto é trivial, a menos que já exista outra conta com o mesmo nome. Depois de modificados userAccountControl e sAMAccountName, o DC está disposto a entregar o hash MS-SNTP a quem pedir apropriadamente. Before computing the hash, the DC also checks that sAMAccountName ends with a dollar sign ($). For Domain Admins, changing this is trivial unless another account with the same name exists. Once userAccountControl and sAMAccountName are modified, the DC is willing to hand out the MS-SNTP hash to anyone asking appropriately.
⚠️ Warning operacional / Operational warning:
Quando uma conta de utilizador é convertida em workstation trust account, o utilizador perde a capacidade de fazer logon em workstations. Isto não afeta sessões ativas existentes. Se reverteres os atributos imediatamente após extrair o hash, o utilizador provavelmente nunca notará nada. When a user account is converted into a workstation trust account, the user loses the ability to log into workstations. This doesn't affect existing active sessions. If you immediately revert the attributes after extracting the hash, the user will likely never notice anything.

5. Exploração Original Complementar

Foi criado um script proof-of-concept modificando o script PowerShell original de Timeroasting de Jacopo Scannella. Para o usar, precisas de ser Domain Admin, correr de um sistema加入 ao domínio, com o módulo ActiveDirectory do PowerShell instalado. A proof-of-concept script was created by modifying Jacopo Scannella's original PowerShell Timeroasting script. To use it, you need to be a Domain Admin, running from a domain-joined system with the ActiveDirectory PowerShell module installed.

5.1 Passos lógicos do script / Script's logical steps Original

O script funciona em vários passos lógicos: (1) obtém objectSid e userAccountControl da conta alvo; (2) altera userAccountControl para workstation trust account; (3) acrescenta $ ao sAMAccountName; (4) extrai o RID, envia pedido MS-SNTP ao DC e obtém o hash; (5) restaura os valores originais. The script works in several logical steps: (1) retrieves objectSid and userAccountControl of the target account; (2) changes userAccountControl to workstation trust account; (3) appends $ to sAMAccountName; (4) extracts the RID, sends MS-SNTP request to the DC and retrieves the hash; (5) restores original values.

5.2 Implementação de referência / Reference implementation Complementar

O artigo não inclui o código-fonte. Abaixo está uma implementação de referência da lógica descrita, para fins de formação. The article doesn't include the source. Below is a reference implementation of the described logic, for training purposes. 
# Targeted-Timeroast.ps1 (reference implementation - lab use only)
param(
  [Parameter(Mandatory)][string]$TargetUser,
  [string]$DomainController = $env:LOGONSERVER.TrimStart('\\')
)
Import-Module ActiveDirectory -EA Stop

# 1. Save original values
$u = Get-ADUser -Identity $TargetUser -Properties objectSid,userAccountControl,sAMAccountName
$origUAC = $u.userAccountControl
$origName = $u.sAMAccountName
$rid = ($u.objectSid.Value -split '-')[-1]

Write-Host "[*] Target: $TargetUser (RID: $rid, UAC: $origUAC)" -ForegroundColor Cyan

# 2. Convert to workstation trust account (0x1000 = WORKSTATION_TRUST_ACCOUNT)
$newUAC = ($origUAC -band (-bnot 0xFFFF)) -bor 0x1000
Set-ADUser -Identity $TargetUser -Replace @{userAccountControl=$newUAC}

# 3. Append $ to sAMAccountName
Set-ADUser -Identity $TargetUser -Replace @{sAMAccountName="$origName$"}

# 4. Send MS-SNTP request and capture hash
# (Use the original Timeroast.ps1 function - omitted here)
# $hash = Invoke-Timeroast -DC $DomainController -RID $rid

# 5. Restore original values
Set-ADUser -Identity $TargetUser -Replace @{sAMAccountName=$origName}
Set-ADUser -Identity $TargetUser -Replace @{userAccountControl=$origUAC}
Write-Host "[+] Restored original attributes" -ForegroundColor Green

# 6. Crack (on attacker host)
# hashcat -m 31300 -a 0 hashes.txt wordlist.txt --username

6. Scripts de Impacto / Impact Scripts Impacto Complementar

Os scripts abaixo ajudam o blue team a detetar atividade compatível com Targeted Timeroasting. The scripts below help the blue team detect Targeted Timeroasting-compatible activity.

6.1 Script 10.1 — Deteção de Alterações a userAccountControl / UAC Change Detection

Objetivo: detetar alterações a userAccountControl em contas de utilizador que as convertam em workstation trust accounts. Evidência: uac-changes.csv. Goal: detect userAccountControl changes on user accounts that convert them to workstation trust accounts. Evidence: uac-changes.csv. 
# Script 10.1 - UAC Anomaly Detection (requires AD module)
Import-Module ActiveDirectory -EA Stop
$out = ".\uac-changes.csv"
$hits = @()
# Find users with WORKSTATION_TRUST_ACCOUNT flag (0x1000) - unusual for users
Get-ADUser -Filter * -Properties userAccountControl,sAMAccountName,whenChanged |
  Where-Object {
    ($_.userAccountControl -band 0x1000) -and
    -not $_.sAMAccountName.EndsWith("$") -and
    $_.whenChanged -gt (Get-Date).AddDays(-7)
  } |
  ForEach-Object {
    $hits += [PSCustomObject]@{ User=$_.sAMAccountName; UAC=$_.userAccountControl; Changed=$_.whenChanged }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] UAC anomalies: $($hits.Count) -> $out" -ForegroundColor Red

6.2 Script 10.2 — Deteção de sAMAccountName com $ em Users / $ Suffix Detection

Objetivo: detetar contas de utilizador cujo sAMAccountName termina em $ (comportamento de máquina) mas que são, de facto, utilizadores. Evidência: dollar-users.csv. Goal: detect user accounts whose sAMAccountName ends with $ (machine behavior) but are actually users. Evidence: dollar-users.csv. 
# Script 10.2 - $ Suffix User Detection (requires AD module)
Import-Module ActiveDirectory -EA Stop
$out = ".\dollar-users.csv"
$hits = @()
Get-ADUser -Filter * -Properties sAMAccountName,objectClass,whenChanged |
  Where-Object { $_.sAMAccountName.EndsWith("$") -and $_.objectClass -eq "user" } |
  ForEach-Object {
    $hits += [PSCustomObject]@{ User=$_.sAMAccountName; Changed=$_.whenChanged }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Users with `$ suffix: $($hits.Count) -> $out" -ForegroundColor Yellow

6.3 Script 10.3 — Auditoria de Contas de Computador com Password Antiga / Legacy Computer Audit

Objetivo: identificar contas de computador com PasswordLastSet antigo (potencialmente vulneráveis ao Timeroasting original). Evidência: legacy-computers.csv. Goal: identify computer accounts with stale PasswordLastSet (potentially vulnerable to original Timeroasting). Evidence: legacy-computers.csv. 
# Script 10.3 - Legacy Computer Account Audit (requires AD module)
Import-Module ActiveDirectory -EA Stop
$out = ".\legacy-computers.csv"
$threshold = (Get-Date).AddDays(-30)
$hits = @()
Get-ADComputer -Filter * -Properties PasswordLastSet,OperatingSystem,whenCreated |
  Where-Object { $_.PasswordLastSet -lt $threshold -or -not $_.PasswordLastSet } |
  ForEach-Object {
    $hits += [PSCustomObject]@{ Computer=$_.Name; OS=$_.OperatingSystem; PwdLastSet=$_.PasswordLastSet; Created=$_.whenCreated }
  }
$hits | Export-Csv $out -NoTypeInformation -Encoding UTF8
Write-Host "[+] Legacy computers (>30d): $($hits.Count) -> $out" -ForegroundColor Red

8. Mitigações Blue Team / Mitigations Complementar

  1. Monitorizar alterações a userAccountControl em contas de utilizador (evento 4738) — qualquer alteração para workstation trust é suspeita.
  2. Alertar sobre sAMAccountName terminado em $ em contas de utilizador.
  3. Auditar contas de computador com passwords antigas (>30 dias) — usar Script 10.3.
  4. Restringir Domain Admin — usar Tier 0 e Protected Users.
  5. Monitorizar tráfego NTP para pedidos anómalos (RIDs sequenciais).
  6. Ativar auditoria de Directory Service Access (evento 4662) para alterações a atributos.
  7. Honeytokens — conta de utilizador com nome semelhante a computador.
